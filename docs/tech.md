# Техническая Документация

## 1. Общая Архитектура
Проект представляет собой асинхронное приложение на Python, работающее в режиме Long Polling (или Webhook в продакшене) для взаимодействия с Telegram Bot API. Приложение построено по модульному принципу с четким разделением слоев: интерфейс (Telegram handlers), бизнес-логика (Services), работа с данными (ORM) и внешние интеграции (LLM).

## 2. Технологический Стек

### Core
*   **Язык:** Python 3.11+
*   **Framework:** aiogram 3.x (асинхронная работа с Telegram API, поддержка FSM).
*   **Конфигурация:** pydantic-settings (валидация переменных окружения .env).

### База Данных и Хранение
*   **СУБД:** PostgreSQL.
*   **ORM:** Tortoise ORM (полностью асинхронная ORM).
*   **Миграции:** Aerich.
*   **Файловое хранилище:** Локальное (на старте) или S3-compatible (в будущем) для хранения загруженных медицинских документов.

### AI и ML
*   **LLM Provider:** OpenAI API.
*   **Модель:** GPT-5.1 (выбрана за мультимодальность — способность нативно обрабатывать изображения документов без промежуточного OCR).

## 3. Ключевые Модули и Сервисы

### Bot Handlers (Слой представления)
*   **Onboarding Handlers:** FSM-диалог для сбора первичной анкеты.
*   **Document Handlers:** Прием фото/документов, валидация форматов, сохранение.
*   **Menu Handlers:** Навигация, профиль, оплата.

### Core Services (Бизнес-логика)
*   **Analysis Service:** Оркестратор процесса анализа. Отправляет промпт и изображение в LLM, получает ответ, сохраняет результат.
*   **Payment Service:** Интеграция с платежным провайдером (Telegram Payments).

## 4. Внешние Интеграции

### Telegram Bot API
*   Взаимодействие с пользователем.
*   Прием файлов.

### OpenAI API
*   Endpoint: Chat Completions API.
*   Использование Vision capabilities для распознавания текста с фото.
*   Системные промпты для медицинской интерпретации и структурирования данных.

## 6. Безопасность
*   Токены и ключи хранятся только в переменных окружения (`.env`).
*   Данные пользователей разделены (доступ только к своим записям).
