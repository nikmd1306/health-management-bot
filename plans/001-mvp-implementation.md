# План реализации MVP: Telegram-бот для анализа здоровья

## Цель
Создать полностью рабочий MVP Telegram-бота, который принимает медицинские документы, анализирует их через OpenAI API и сохраняет историю. Реализация должна соответствовать архитектуре из `docs/tech.md` и продуктовым требованиям из `docs/product.md`.

## Технологический стек
*   **Язык:** Python 3.11+
*   **Telegram Framework:** aiogram 3.x
*   **Database:** PostgreSQL (запуск через Docker Compose) + Tortoise ORM
*   **Migrations:** Aerich
*   **AI:** OpenAI API (GPT-5.1)
*   **Config:** pydantic-settings

## Этапы реализации

### Этап 1: Инициализация проекта и инфраструктуры
1.  Настроить управление зависимостями (uv).
2.  Создать структуру проекта согласно `docs/tech.md` (`handlers/`, `services/`, `database/`).
3.  Настроить конфигурацию через `pydantic-settings` и `.env`.
4.  Создать `docker-compose.yml` для запуска PostgreSQL.
5.  Настроить базовый логгинг.

### Этап 2: База данных и модели
1.  Настроить подключение Tortoise ORM.
2.  Создать модель `User`:
    *   `telegram_id` (BigInt, PK/Unique)
    *   `username`, `full_name`
    *   `is_premium` (bool)
    *   Поля анкеты: `age`, `gender`, `complaints` (Text).
3.  Создать модель `Analysis` (Медицинский документ):
    *   `id` (UUID/Auto)
    *   `user` (ForeignKey -> User)
    *   `original_file_id` (Telegram file ID)
    *   `analysis_text` (Результат от LLM)
    *   `created_at`.
4.  Настроить и инициализировать Aerich для миграций.

### Этап 3: Основа бота (Bot Foundation)
1.  Инициализировать `Bot` и `Dispatcher` (aiogram).
2.  Настроить Middleware:
    *   `AuthMiddleware`: автоматическое создание/обновление пользователя в БД при любом взаимодействии.
3.  Создать базовые хендлеры: `/start`, `/help`.
4.  Реализовать главное меню (ReplyKeyboardMarkup): "Анализ", "Профиль", "Подписка".

### Этап 4: Модуль Onboarding (Анкетирование)
1.  Определить FSM состояния: `OnboardingSG` (Age, Gender, Context).
2.  Реализовать сценарий:
    *   При первом запуске или по команде — запуск опроса.
    *   Валидация ответов.
    *   Сохранение данных в профиль пользователя.

### Этап 5: Сервис анализа документов (Core Magic)
1.  Реализовать `AnalysisService`:
    *   Метод `analyze_document(file_path/url)` -> текст.
    *   Интеграция с OpenAI Chat Completions API (Vision preview).
    *   Системный промпт для роли "Медицинский ассистент".
2.  Реализовать хендлеры приема файлов:
    *   Обработка `content_types=[Photo, Document]`.
    *   Проверка лимитов (размер, кол-во).
    *   Отправка файла в сервис.
    *   Отправка результата пользователю.

### Этап 6: Профиль и История
1.  Хендлер для кнопки "Профиль": отображение данных анкеты и статуса подписки.
2.  Хендлер для кнопки "История": список последних 5 анализов (или пагинация).

### Этап 7: Монетизация (MVP Paywall)
1.  Реализовать простой механизм "Premium" доступа.
2.  Хендлер "Подписка":
    *   (Для MVP) Тестовая кнопка оплаты через Telegram Payments (или заглушка, если нет токена кассы).
    *   Активация `is_premium = True` после "оплаты".
3.  Ограничение для бесплатных пользователей (например, только 1 анализ или скрытие детальной расшифровки).

### Этап 8: Финализация
1.  Финальное тестирование User Flow.
2.  Обновление `README.md` (инструкция по запуску).

## Риски
*   **OpenAI API Costs:** Обработка изображений может быть дорогой.
*   **Telegram File Size:** Боты имеют лимит на скачивание файлов (20MB).
*   **Privacy:** Передача медицинских данных в OpenAI (требуется дисклеймер).
